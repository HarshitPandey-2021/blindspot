# PART I — THE PROJECT

## 1. One page

A convolutional neural network distinguishes real photographs from StyleGAN-generated faces
with **95.22%** accuracy. A perturbation of roughly **one brightness level out of 255** —
invisible to the human eye, and one that survives being saved as an ordinary 8-bit image —
drives it to **0.00%** on all 6,000 held-out validation images.

Adversarial training recovers about half the model's skill at small perturbations and costs
**24.5 points** of clean accuracy.

Along the way the project measures the vanishing gradient problem directly, demonstrates the
exploding gradient problem by accident, and documents three experiments that failed.

**Build it. Break it. Fix it.**

## 2. Why this project

### The practical case

Detectors of this kind are deployed now:

- **Content moderation** — platforms flag AI-generated images automatically
- **KYC / identity verification** — banks check that an uploaded selfie is a real person
- **The reverse harm** — pushing a *real* person's genuine photograph over the line into
  "fake", so an innocent user is flagged. Rarely tested. This project tests it.
- **The general lesson** — this is not a bug in one model. Every neural network trained the
  ordinary way has this property.

### Why this shape of project

Most student projects build a classifier that already exists, and the awkward question is
"which part did you build?" This one builds a working system and then **attacks it and
measures where it breaks**, which is the shape of research rather than of a tutorial.

There is also a structural reason the viva is safe: FGSM computes the gradient of the loss
with respect to the **input pixels** instead of the weights. It is backpropagation stopped
one step earlier and pointed elsewhere. So every question about gradients is a question
about this project's own code.

# PART II — WHAT WAS BUILT

## 4. Dataset

**140k Real and Fake Faces** (xhlulu, Kaggle). 70,000 real photographs from Flickr/FFHQ and
70,000 generated by StyleGAN.

```
train  100,000      valid  20,000      test  20,000
labels: fake = 0, real = 1
loaded at 128×128 RGB
```

Experiments use a 45,000-image training subset and 6,000-image validation and test samples,
drawn with fixed seeds so every number is comparable across days.

**Test set discipline:** reserved from Day 3 and touched exactly once, at the end. Every
tuning decision was made on validation.

## 5. The detector

Four blocks, each `Conv2d(3×3, padding=1) → BatchNorm2d → ReLU → MaxPool2d(2)`, channels
3 → 32 → 64 → 128 → 128, image 128×128 → 8×8. Then `AdaptiveAvgPool2d(1)`, `Flatten`,
`Linear(128, 2)`.

**241,794 parameters.** Adam, lr 3e-4 with cosine decay, random horizontal flips, 25 epochs.

**Trained from scratch, not fine-tuned from a pretrained backbone.** Transfer learning would
score higher; the project is about the mechanism, not the leaderboard. Saying this plainly is
a stronger answer than pretending not to know about it.

The global average pooling is a direct consequence of a Day 2 measurement: the convolutions
cost about 18,800 parameters while a dense head cost over 400,000. Pooling removes that head.

## 6. The attack

```
x_adv = clamp( x + ε · sign( ∂Loss/∂x ) , 0, 1 )
```

Implemented from scratch, not imported.

Training computes the gradient of the loss with respect to the **weights** — "how should the
model change to be less wrong?" This computes it with respect to the **input pixels** and
steps the other way: "how should the picture change to make the model more wrong?"

Taking the **sign** rather than the raw gradient bounds every pixel to exactly ε regardless of
how steep the gradient is. That bound is what keeps the perturbation invisible; the raw
gradient would move some pixels enormously and others barely at all.

**PGD** is the same idea applied ten times with small steps, projected back into the ε-ball
after each one. Strictly stronger.

## 7. The defence

**Adversarial training.** Each batch, FGSM examples are generated from the *current* model and
the network trains on clean and attacked images together, both with correct labels. 12 epochs,
ε = 0.01, started from the trained detector.

# PART III — THE EXPERIMENTAL RECORD

## Day 1 (29 Oct) — first model, and the vanishing gradient

MLP on MNIST, 784 → 256 → 10: **94.39% → 96.41% → 96.98%**.

Then a deliberately bad 20-layer network, one backward pass, mean |gradient| per layer:

```
sigmoid   layer 1  1.722e-19    last  2.325e-02    ratio 1.35e17
relu      layer 1  4.328e-11    last  6.420e-04    ratio 1.48e7
```

Both lines straight on a log axis — exponential decay, which is exactly what repeated
multiplication by the chain rule predicts. Sigmoid loses a factor of about **8× per layer**,
ReLU about **2.4× per layer**.

**Finding:** ReLU improved layer 1 by a factor of 100 million and still left it at `4.3e-11` —
far too weak to learn from. **ReLU alone does not fix the problem.**

## Day 2 (30 Oct) — the right architecture

Same task, two shapes, identical budget:

```
MLP   97.10%    290 errors / 10,000    203,530 params
CNN   98.70%    130 errors / 10,000    421,642 params
```

Errors more than halved. **Finding with a twist:** the CNN has *more* total parameters, but
only ~18,800 sit in the convolutions — the `Linear(3136,128)` head holds the rest. The
convolutions beat a 200,000-parameter dense layer using 18,800.

## Day 3 (30 Oct) — the data

No training, deliberately: if the data load is wrong *and* training runs, you cannot tell which
broke.

**Observation recorded:** real photos are varied and messy; fakes are all tidy centred
portraits. Risk flagged — the model might learn "tidy framing = fake" and score well for
entirely the wrong reason. Marked for testing on Day 5.

## Day 4 (31 Oct) — training the detector

### The 120× slowdown

First run: 970 seconds for one epoch over 30,000 images. Profiling showed the GPU idle.
`/kaggle/input` is network-mounted and the dataset is 140,000 small JPEGs; throughput was
~31 images/second. **Disk-bound, not compute-bound.**

Fix: preload a subset into GPU memory once as `uint8` and train from there.
**Epochs went from ~16 minutes to 8 seconds.**

### Three runs

```
v1   20k @  96px,  lr 1e-3                          valid 0.9137
v2   20k @  96px,  lr 3e-4 + cosine + flips, 25 ep  valid 0.9050
v3   45k @ 128px,  same optimiser settings          valid 0.9522   (train 0.9912)
```

**v1** worked but validation swung ±30 points between epochs (0.70, 0.59, 0.86, 0.53) while
training climbed smoothly. Diagnosis: learning rate too high. Training accuracy is averaged
*across* an epoch so it hides oscillation; validation is a single snapshot at epoch end.

**v2** tested that. The swinging stopped exactly when cosine decay pulled the rate below
~1.4e-4 — epochs 13–25 climbed smoothly from 0.867 to 0.905. **Diagnosis confirmed, peak
unchanged.** So optimisation was *not* the bottleneck.

**v3** changed the data instead. **+4 points.** StyleGAN artifacts are high-frequency detail
and 96px was destroying them.

**Operational note:** both `.pth` files were lost to a Kaggle session timeout. Retrained.
Rule adopted: download weights the moment training ends.

## Day 5 (31 Oct) — interrogating the detector

### Confusion matrix (6,000 validation images)

```
            said fake    said real
is fake       2,809         163        94.52% of fakes caught
is real         124       2,904        95.90% of reals passed
```

Slightly weaker at catching fakes. **The two errors are not equally costly:** 163 fakes
through is a verification bypass; 124 reals flagged is innocent users rejected.

287 wrong of 6,000. The confident mistakes cluster on **occlusions and atypical faces** —
sunglasses, glasses, hats, a wide-open mouth, a young child.

### The shortcut-learning test

```
original          0.9522
blurred           0.5085     collapsed to chance
border removed    0.8553     mostly held
```

Blur destroys fine texture while leaving composition intact. If the model had been keying on
framing, blur would barely have touched it. **It collapsed to random instead — the model reads
high-frequency texture, which is where StyleGAN leaves its fingerprints. Day 3 worry refuted.**

### A prediction, recorded in advance

> FGSM produces a small high-frequency perturbation. This detector depends on high-frequency
> texture. It should therefore be unusually easy to fool — accuracy should collapse at very
> small epsilon.

Written 31 October, before any attack code existed. Confirmed 5 November.

## Day 6 (31 Oct) — the depth sweep

Gradient profile at initialisation, sigmoid MLPs, one backward pass each:

```
 5 layers   layer 1  1.520e-06    ratio 2.6e4
10 layers   layer 1  3.737e-11    ratio 7.5e8
20 layers   layer 1  1.788e-19    ratio 2.3e20
40 layers   layer 1  3.659e-37    ratio 3.8e39
```

**Doubling depth squares the ratio.**

### A failed experiment, kept deliberately

The first training attempt returned exactly **0.5047** at every depth — that is 3,028/6,000,
the "always predict real" baseline. Every network collapsed, including the 5-layer one.

**With no positive control the result was uninterpretable.** It could not distinguish "depth
killed it" from "the setup is broken."

Causes: 49,152 raw inputs into a sigmoid saturates it even at 5 layers, and the inputs were
not zero-centred. A CUDA out-of-memory error also appeared from converting 45,000 images to
float in a single operation.

Fix: 32×32 input, centred to [−1, 1], and **always run a control that must succeed.**

### Second attempt (8 epochs, plain SGD lr 0.1)

```
CONTROL   relu  5 layers   0.7122      control passes, setup is sound
sigmoid   5/10/20/40       0.5047      all = always-predict-real
relu      10/20/40         0.4953      all = always-predict-fake (2972/6000)
```

Sigmoid fails at every depth, even 5 — predicted by the gradient profile. ReLU rescues depth 5
only. The dead networks collapsed to **constant predictors**, not weak learners; this was
checked rather than assumed.

**Why plain SGD and not Adam:** Adam adapts the step size per weight from gradient history, so
it compensates for tiny gradients and partially masks the phenomenon. SGD multiplies by the
learning rate and nothing else.

## Day 7 (31 Oct) — the four fixes

### Gradient flow, 20-layer networks

```
sigmoid              layer 1  3.617e-19   last 1.514e-01   ratio 4.19e17
relu                 layer 1  5.945e-11   last 5.811e-04   ratio 9.77e6
relu + He init       layer 1  2.840e-03   last 5.631e-02   ratio 19.8
relu + He + BN       layer 1  1.060e-01   last 8.394e-02   ratio 0.8     near-perfect
residual + He        layer 1  2.698e+01   last 2.582e+03   ratio 95.7    ~1000× TOO LARGE
residual + BN + He   layer 1  2.971e-02   last 4.004e+00   ratio 134.8   BN cut it ~900×
```

### Accuracy

```
config               d=5      d=10     d=20     d=40
sigmoid              0.5047   0.5047   0.5047   0.5047
relu                 0.7122   0.4953   0.4953   0.4953
relu + He            0.7943   0.6552   0.7840   0.7692
relu + He + BN       0.8173   0.7972   0.7363   0.5287
residual + He        0.7732   0.4953   0.4953   0.4953
residual + BN + He   0.7760   0.7713   0.5995   0.5108
```

### Findings

1. **He initialisation is the single biggest win** — moves the depth wall from 5 to beyond 40.
2. **Batch norm** gives the best shallow accuracy (0.8173 at d=5) and the best gradient ratio
   (0.8), but degrades with depth and collapses at 40.
3. **Exploding gradients, unplanned.** Residual-only gradients were ~1000× too *large*.
   `y = x + f(x)` accumulates signal through the stack, so at lr 0.1 every update overshoots.
   Both syllabus failure modes now demonstrated from own runs.
4. Adding BN to the residual network cut magnitudes ~900× and rescued depth 10
   (0.4953 → 0.7713). **This is exactly why real ResNets pair skip connections with
   normalization.**
5. **The overall winner at depth is the simplest fix** — ReLU + He init alone, 0.7692 at 40
   layers. The prediction that residual+BN would win was **wrong**.
6. **Healthy gradient flow is necessary but not sufficient.** Residual-only had a reasonable
   ratio (95.7) and still failed, because the magnitudes were wrong.

**Caveats:** single seed; lr fixed at 0.1 for every architecture, never tuned per-config;
8 epochs may be too few for the larger residual+BN network.

## Days 9–12 (5 Nov) — attack and defence

Sanity check passed: baseline clean 0.9522, matching Day 4 exactly.

### Single image

Validation image #0, ε = 0.01: **fake (0.9995) → real (1.0000)**. Largest pixel change
**2.6/255**. Visually identical.

### Epsilon sweep, undefended, 6,000 images

```
eps     (x/255)    FGSM      PGD-10
0.000   ( 0.0)     0.9522    0.9522
0.001   ( 0.3)     0.0090    0.0013
0.002   ( 0.5)     0.0000    0.0000
0.005   ( 1.3)     0.0000    0.0000
0.010   ( 2.6)     0.0000    0.0000
0.020   ( 5.1)     0.0050    0.0000
0.030   ( 7.6)     0.0545    0.0000
0.050   (12.8)     0.1517    0.0000
0.100   (25.5)     0.0110    0.0000
```

**Collapse is total by ε = 0.002.** Not one of 6,000 images survived.

**The non-monotonic FGSM line at ε 0.02–0.05** is the one-step attack overshooting the
adversarial region on a curved loss surface. PGD stays at 0.0000 at every one of those
epsilons, proving the adversarial examples are still there. A property of the *attack*, not
robustness of the model.

### Both directions

At ε 0.002, 0.005 and 0.010, both fake→real (evasion) and real→fake (false accusation) are
**0.0000**. Both harms are equally available to an attacker.

### The defence

Clean accuracy 0.9522 → **0.7072**. Cost: **24.5 points.**


## Day 13 (5 Nov) — diagnostics

### 8-bit quantization — does the attack survive being saved as a real file?

```
eps     (x/255)    float     8-bit
0.001   ( 0.3)     0.0090    0.9522     rounds away entirely
0.002   ( 0.5)     0.0000    0.0000
0.005   ( 1.3)     0.0000    0.0000
0.010   ( 2.6)     0.0000    0.0002
0.020   ( 5.1)     0.0050    0.0047
```

**ε = 0.005 (1.3/255) is the real-world headline** — it survives 8-bit rounding and still
gives 0% accuracy. ε = 0.001 is a floating-point artifact and must not be quoted.

### Frequency reliance — testing why the defence cost so much

```
sigma    undefended    defended
0        0.9522        0.7072
0.5      0.9425        0.7035
1.0      0.6928        0.6957
1.5      0.5245        0.6883
2.0      0.5085        0.6747
3.0      0.5052        0.6562

fraction of accuracy lost at sigma 2.0:
  undefended  0.466
  defended    0.046
```

**Hypothesis supported.** The undefended model loses 47% of its accuracy when fine texture is
removed; the defended model loses 5%. Adversarial training moved the model off high-frequency
features onto coarser ones — and that migration is what the 24.5 points bought.

# PART IV — WHAT IT MEANS

## 8. Reading the defence honestly

**In absolute terms it is modest.** At the budget it was trained on (ε 0.01) the defended model
scores 0.5080 against PGD, against a 0.5047 always-predict-one-class baseline. Against a
full-strength attack at that budget, the defence buys essentially nothing.

**Measured as skill above chance**, at ε = 0.005:

```
                    accuracy     skill above chance
undefended clean     0.9522          +0.4475
undefended @0.005    0.0000          −0.5047
defended   clean     0.7072          +0.2025
defended   @0.005    0.6095          +0.1048
```

The defended model retains about **52% of its skill**. The undefended model does not merely
lose its skill — it goes **negative**.

## 9. The most striking single result

At 0% accuracy the detector is not broken. It is **perfectly wrong**. Invert every answer it
gives and you would score 100%. The attack does not blind the detector; it inverts it into a
reliable liar.

## 10. Is it gradient masking?

Three of the four standard checks pass on the existing data:

- PGD is at least as strong as FGSM at every epsilon (under masking, PGD is often *weaker*)
- Accuracy decreases monotonically with epsilon
- Accuracy approaches zero at large epsilon rather than hitting a floor

The fourth — a transfer attack crafted on the undefended model and evaluated on the defended
one — remains to be run.

## 11. What this project does **not** show

Stated deliberately.

- **Not that this detector is more fragile than others.** No reference model was trained, so
  "extremely fragile" is supported; "unusually fragile" is not.
- **Not that the attack survives JPEG.** Only 8-bit rounding was tested. JPEG also removes
  high frequencies, so both the attack *and* the detector would likely degrade.
- **Not black-box.** Every attack here had full access to the model's weights.
- **Not that ε = 0.01 was the right training budget** for the defence. Never isolated.
- Single seed throughout.

## 12. Things that went wrong

- The first training run was **120× too slow**; profiling found it disk-bound, not
  compute-bound.
- An early depth experiment returned identical results at every depth and was therefore
  **uninterpretable** — no positive control.
- A prediction that residual + batch norm would win at depth was **wrong**; plain He
  initialisation beat it.
- Both trained models were lost once to a session timeout.
- An early version of the defence chart was titled "restores robustness", which overclaimed.
  Corrected to "trades clean accuracy for partial robustness."

All dated in `lab-notebook.md`.

## 15. Viva question bank

**On the attack**

- *Why the sign of the gradient and not the gradient itself?* Sign bounds the per-pixel change
  to exactly ε regardless of gradient steepness — that bound is what keeps it invisible.
- *White-box or black-box?* White-box: full access to the weights. Black-box would require
  transfer attacks or gradient estimation from queries alone.
- *Why is PGD stronger than FGSM at the same budget?* FGSM takes one large step and can
  overshoot on a curved surface; PGD takes ten small projected steps and finds a better point
  inside the same ε-ball.
- *Would it survive JPEG?* I tested 8-bit rounding and it survives at ε 0.005. I did not test
  JPEG, which also removes high frequencies — I'd expect both the attack and the detector to
  degrade, and that's a real gap in the work.

**On the defence**

- *Did it work?* Partly, and the answer depends on how you measure. In absolute terms, at the
  trained budget it is barely above the majority-class baseline against PGD. Measured as skill
  above chance at a smaller budget, it keeps about half its skill where the undefended model
  goes negative. Both numbers belong in the report.
- *Why did clean accuracy drop 24.5 points?* I tested a hypothesis rather than guessing. The
  detector depends on high-frequency texture; FGSM lives in the same band; so robustness
  training fights the feature the detector needs. The blur test confirms the defended model
  shifted onto coarser features — losing 5% under blur where the undefended model loses 47%.
- *How do you know it isn't gradient masking?* Three standard checks pass: PGD is never weaker
  than FGSM, accuracy falls monotonically, and it reaches ~0 at large ε with no floor.

**On gradients**

- *What causes vanishing gradients?* Backprop multiplies by each layer's derivative on the way
  back. Sigmoid's derivative is at most 0.25, so twenty layers means twenty multiplications by
  a number below one.
- *How do you know that's the cause?* Every line in my measurement is straight on a log axis.
  A constant shrinking factor per layer is exactly what repeated multiplication predicts; any
  other cause would curve the line.
- *Why did you use SGD instead of Adam for those experiments?* Adam adapts step size per weight
  and compensates for tiny gradients, masking the phenomenon. SGD does not.
- *What is the exploding gradient problem?* The mirror image, and I hit it by accident:
  residual connections without normalization accumulate signal through the stack and produced
  gradients ~1000× too large.

**On the model**

- *Why not transfer learning?* It would score higher. I trained from scratch because the
  project is about the mechanism, and because attacking a network whose every layer I chose is
  a cleaner experiment.
- *How do you know it learned something real?* The blur test. Destroying fine texture while
  keeping composition collapses it to chance, which means it reads AI artifacts rather than
  image framing.

## 16. Glossary

| Term | One line |
|---|---|
| Tensor | An array of numbers that tracks its own history so gradients can be computed |
| Weight | A number inside the model, adjusted during training |
| Loss | A single number measuring how wrong the model is right now |
| Gradient | Which direction to nudge something to reduce the loss |
| Backpropagation | The algorithm computing gradients for every weight at once |
| Epoch | One full pass through the training data |
| Batch | A group processed together before one weight update |
| Learning rate | How big each nudge is |
| Overfitting | Memorising the training data instead of learning the pattern |
| Epsilon (ε) | How much each pixel may be changed in the attack |
| FGSM | One-step attack: nudge pixels once in the direction that hurts most |
| PGD | Multi-step FGSM, projected back into the ε-ball each step |
| White-box | The attacker has the model's weights |
| He initialisation | Weight scaling tuned for ReLU, so the signal doesn't shrink per layer |
